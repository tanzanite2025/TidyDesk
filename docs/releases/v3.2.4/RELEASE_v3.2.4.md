## 🔧 技术改进

### 缓存机制

- **缓存位置**: `%APPDATA%/TidyDesk/cache/apps.json`
- **缓存内容**: 应用列表 + 图标（Base64）
- **缓存大小**: ~500KB（约 127 个应用）
- **缓存 TTL**: 24 小时
- **版本控制**: 自动失效不兼容的缓存

### 性能瓶颈分析

**扫描时间分布**:
- 文件系统扫描: 1-2s (20%)
- 图标获取 `app.getFileIcon()`: 6-10s (80%) ← 真正的瓶颈

**缓存效果**:
- 缓存命中: < 100ms（读取 JSON 文件）
- 缓存未命中: 8-12s（完整扫描）

### 为什么不用 Rust/WASM？

很多人可能会问：为什么不用 Rust 或 WASM 来优化性能？

**答案**: 因为瓶颈在 I/O 和 Electron API，不在计算！

- Rust/WASM 只能优化计算密集型任务
- 80% 的时间花在 `app.getFileIcon()` 这个 Electron API 上
- 缓存直接跳过 I/O，效果最好
- 实现简单（30 分钟），维护容易

**方案对比**:

| 方案 | 性能提升 | 实现成本 | 维护成本 | 推荐度 |
|------|----------|----------|----------|--------|
| **缓存** | 90%+ | 0.5h | 低 | ⭐⭐⭐⭐⭐ |
| 后台扫描 | 95%+ | 2h | 低 | ⭐⭐⭐⭐ |
| Rust 原生 | < 20% | 20h+ | 高 | ⭐ |
| WASM | < 0.5% | 15h+ | 高 | ❌ |

## 🎯 使用指南

### 正常使用

1. **首次打开应用选择器**
   - 会扫描所有已安装的应用（6-12 秒）
   - 自动缓存结果

2. **后续打开**
   - 直接使用缓存（< 1 秒）
   - 底部显示缓存时间

3. **手动刷新**
   - 点击右上角"刷新"按钮
   - 重新扫描应用（6-12 秒）
   - 更新缓存

### 缓存管理

- **自动过期**: 24 小时后自动失效
- **手动刷新**: 点击"刷新"按钮
- **缓存位置**: `%APPDATA%/TidyDesk/cache/apps.json`
- **清除缓存**: 删除缓存文件即可
