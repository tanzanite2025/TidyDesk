## 阶段 2: 错误修复和稳定性提升

**时间**: 2026-05-24 18:00 - 18:50  
**目标**: 修复崩溃问题，进一步优化性能

### 问题诊断

1. **ResourceMonitor 错误日志**
   - PowerShell 查询不存在的进程
   - 大量错误输出到 stderr

2. **Network Service 崩溃**
   - Electron 内部问题
   - 自动重启，但看起来像崩溃

3. **缓存文件损坏**
   - 导致应用无限循环
   - 需要手动删除

4. **进程泄漏**
   - 旧进程没有完全退出
   - 多个主进程同时运行

### 修复内容

1. **ResourceMonitor 错误处理**
   ```javascript
   // 添加 2>$null 重定向 stderr
   const output = execSync(
     `powershell -Command "Get-Process -Id ${pid} -ErrorAction SilentlyContinue | Select-Object CPU, HandleCount | ConvertTo-Json" 2>$null`,
     { encoding: 'utf8', timeout: 3000 }
   );
   
   // 检查空输出
   if (!output || !output.trim()) {
     return { cpu: 0, handles: 0 };
   }
   ```

2. **Network Service 崩溃监听**
   ```javascript
   app.on('child-process-gone', (event, details) => {
     console.warn('[TIDYDESK] Child process gone:', details);
     
     if (details.type === 'Utility' && details.name === 'network.mojom.NetworkService') {
       console.log('[TIDYDESK] Network service crashed, Electron will restart it automatically');
     }
   });
   ```

3. **缓存文件处理**
   - 自动删除损坏的缓存
   - 使用原子写入（临时文件 + 重命名）
   - 添加 JSON 验证

4. **进程清理**
   - 强制杀掉所有旧进程
   - 确保单实例锁定正常工作

### 效果

句柄数量: 3392 → 2689 (-21%)

## 关键发现

### 1. 进程泄漏的根本原因

**不是代码问题，而是操作问题**:
- 旧进程没有完全退出
- 多次启动应用导致多个主进程
- 每个主进程创建自己的子进程

**解决方案**:
- 启动前强制杀掉所有旧进程
- 确保单实例锁定正常工作

### 2. 应用崩溃的根本原因

**不是性能监控的问题**:
- 缓存文件损坏导致无限循环
- Network Service 崩溃（Electron 内部问题）
- PowerShell 错误日志污染控制台

**解决方案**:
- 自动删除损坏的缓存
- 使用原子写入
- 抑制 PowerShell 错误输出

### 3. 句柄数量增加的原因

**阶段 1 后句柄数量反而增加**:
- 起点: 2162
- 阶段 1: 3392 (+57%)
- 阶段 2: 2689 (-21%)

**可能原因**:
- 性能监控系统本身占用句柄
- 定时器和监听器未清理
- 文件监控占用句柄

**下一步**: 审查所有资源管理
